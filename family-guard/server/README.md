# SAHROUD FAMILY GUARD — API

این پوشه شامل API مبتنی بر Cloudflare Worker و طرح پایگاه داده D1 است. راهنمای کامل راه‌اندازی داشبورد Cloudflare در فایل DEPLOY-CLOUDFLARE.md قرار دارد.

## Endpointهای موجود

- GET /health — بررسی سلامت سرویس.
- POST /v1/families — ایجاد خانواده و صدور توکن والد.
- POST /v1/invites — ایجاد کد دعوت یک‌بارمصرف با اعتبار ۱۰ دقیقه.
- POST /v1/devices/pair — اتصال دستگاه پس از پذیرش صریح رضایت.
- POST /v1/location — دریافت مختصات از دستگاه دارای توکن.
- GET /v1/family/devices — فهرست دستگاه‌ها و آخرین موقعیت ثبت‌شده.
- POST /v1/devices/sharing/stop — توقف اشتراک‌گذاری از سمت صاحب دستگاه.
- POST /v1/family/devices/{device_id}/revoke — لغو دسترسی دستگاه توسط والد.

توکن‌های والد و دستگاه به‌صورت تصادفی تولید می‌شوند و فقط هش SHA-256 آن‌ها در D1 ذخیره می‌شود. کد دعوت یک‌بارمصرف و ده‌دقیقه‌ای است. زمان ثبت موقعیت روی گوشی و زمان دریافت در سرور جداگانه نگهداری می‌شوند.

## اتصال Android

در اپ اندروید، صفحهٔ اتصال با کد دعوت و رضایت صاحب دستگاه، ذخیرهٔ رمزنگاری‌شدهٔ توکن دستگاه و ارسال مختصات هنگام فعال بودن سرویس مکان‌یابی پیاده‌سازی شده است. ساخت Debug APK در GitHub Actions موفق بوده است؛ با این حال آزمون عملی دو گوشی و اتصال به Worker مستقرشده هنوز باید انجام شود.

## راه‌اندازی

مراحل ساخت D1، بارگذاری schema، استقرار Worker، تنظیم D1 binding و انتشار داشبورد Pages در فایل زیر آمده است:

- DEPLOY-CLOUDFLARE.md

فایل wrangler.toml دارای placeholder برای Database ID و origin داشبورد است. مقادیر واقعی باید در محیط Cloudflare تنظیم شوند. هیچ توکن یا secret را در GitHub commit نکنید.

## بازیابی امن کلید والد

برای فعال‌کردن بازیابی، در تنظیمات Worker آزمایشی یک Secret با نام `PARENT_RECOVERY_KEY` تعریف کنید. مقدار آن باید تصادفی و حداقل ۳۲ نویسه باشد؛ آن را در GitHub، کد منبع یا پیام‌رسان قرار ندهید. پنل آزمایشی در بخش «بازیابی امن کلید والد» همین مقدار را از شما می‌گیرد و به‌صورت مستقیم از مرورگر به Worker می‌فرستد.

مسیر `POST /v1/owner/recover` فقط با Secret معتبر کار می‌کند و فقط در صورت وجود دقیقاً یک والد اصلی فعال، توکن او را تعویض می‌کند. کلید قدیمی بلافاصله نامعتبر می‌شود؛ خانواده، دستگاه‌های متصل، رضایت دستگاه و تاریخچهٔ موقعیت تغییر یا حذف نمی‌شوند. کلید جدید فقط یک بار به پنل برگردانده می‌شود و باید همان موقع در محل امن ذخیره شود.

پس از بازیابی موفق، Secret را از تنظیمات Worker حذف کنید تا مسیر بازیابی دوباره فعال نباشد. برای بازیابی بعدی باید Secret تازه‌ای در تنظیمات Worker قرار دهید. این قابلیت را فقط در Worker آزمایشی و پس از بررسی کد به کار ببرید؛ آن را به Worker عملیاتی منتقل نکنید مگر پس از آزمون امنیتی.

## محدودیت‌های فعلی

این نسخه هنوز محصول کامل و آمادهٔ استفادهٔ حساس یا عرضهٔ عمومی نیست. داشبورد آخرین موقعیت را نشان می‌دهد، نه مسیر کامل تاریخچه. بازیابی حساب والد، rate limiting و کنترل تلاش کد دعوت، چرخش توکن، مدیریت نگهداری/حذف داده، پایش عملیاتی و آزمون امنیت و بار پیش از بهره‌برداری عمومی لازم‌اند. ظرفیت هدف ۱۰۰۰ تا ۱۰۰هزار کاربر بدون آزمون بار و طراحی/تنظیم زیرساخت تضمین‌شده نیست.

مکان‌یابی باید شفاف و با رضایت صاحب دستگاه باشد. صاحب دستگاه می‌تواند اشتراک‌گذاری را متوقف کند و خاموش‌کردن GPS، اینترنت یا مجوزهای سیستم‌عامل می‌تواند ارسال موقعیت را متوقف کند.


## مدل دو والد و اشتراک
- والد اصلی (owner) از اشتراک خانوادگی پایه استفاده می‌کند و حساب او شامل طرح پایه است.
- والد دوم (second_parent) حساب و توکن مستقل دارد؛ دسترسی به فهرست دستگاه‌ها و تاریخچه فقط با اشتراک جداگانه و فعال او مجاز است.
- دعوت والد دوم فقط توسط والد اصلی انجام می‌شود و کد آن یک‌بارمصرف و ده‌دقیقه‌ای است.
- در این مرحله ایجاد حساب والد دوم و کنترل وضعیت اشتراک پیاده شده؛ اتصال درگاه پرداخت و فعال‌سازی خودکار اشتراک هنوز پیاده‌سازی نشده است. وضعیت والد دوم پس از ثبت‌نام inactive می‌ماند تا سازوکار پرداخت/تأیید اشتراک در مرحله بعد اضافه شود.
- قبل از استقرار نسخه جدید، migration شماره 0002 را یک‌بار روی D1 موجود اجرا کنید. این migration توکن والد فعلی را حفظ و به عضویت owner تبدیل می‌کند؛ داده‌های قبلی حذف نمی‌شوند.
