# راه‌اندازی Cloudflare برای SAHROUD FAMILY GUARD

این راهنما سرویس ابری را به‌صورت مرحله‌ای راه‌اندازی می‌کند. Cloudflare یک سرویس مستقل اینترنتی است؛ افزونهٔ مرورگر یا بخشی از اندروید نیست. برای این پروژه از سه بخش استفاده می‌شود:

- D1: پایگاه دادهٔ خانواده‌ها، دستگاه‌ها، کدهای دعوت و موقعیت‌ها.
- Workers: اجرای API و احراز هویت درخواست‌ها.
- Pages: میزبانی پنل وب والدین.

> تا پایان این مراحل، اپ و پنل به سرور واقعی متصل نیستند. کلید والد و کد دعوت را عمومی نکنید. مکان‌یابی فقط با اطلاع و رضایت صاحب دستگاه انجام شود.

## بخش ۱ — ساخت پایگاه داده D1

1. وارد https://dash.cloudflare.com شوید و حساب کاربری بسازید یا وارد شوید.
2. از منوی چپ Storage & databases → D1 SQL Database را باز کنید.
3. روی Create database بزنید.
4. نام دیتابیس را دقیقاً sahroud-family-guard بگذارید و ایجاد کنید.
5. صفحهٔ دیتابیس را باز کنید و مقدار Database ID را کپی و نزد خود نگه دارید.
6. به زبانهٔ Console یا SQL بروید.
7. فایل schema.sql در GitHub را باز کنید، تمام SQL را کپی کنید و در کنسول D1 اجرا کنید:
   https://github.com/sahroud/danky/blob/main/family-guard/server/schema.sql
8. مطمئن شوید چهار جدول families، devices، invites و locations ساخته شده‌اند.
9. برای حفظ خانواده‌ها و توکن‌های قبلی و افزودن حساب مستقل والد دوم، فایل مهاجرت زیر را نیز یک‌بار در کنسول D1 اجرا کنید:
   https://github.com/sahroud/danky/blob/main/family-guard/server/migrations/0002_multi_parent.sql
10. پس از اجرای موفق مهاجرت، جدول‌های family_members و parent_invites نیز باید وجود داشته باشند. مهاجرت، توکن والد فعلی را به نقش والد اصلی منتقل می‌کند و داده‌های قبلی را حذف نمی‌کند.

## بخش ۲ — ساخت Worker API

1. در Cloudflare از Workers & Pages گزینهٔ Create و سپس Worker را انتخاب کنید.
2. نام Worker را sahroud-family-guard-api قرار دهید و آن را ایجاد کنید.
3. فایل زیر را در GitHub باز کنید و محتوای کامل آن را کپی کنید:
   https://github.com/sahroud/danky/blob/main/family-guard/server/src/index.js
4. در داشبورد Worker گزینهٔ Edit code را بزنید، کد نمونه را با محتوای کامل فایل جایگزین و Deploy کنید.
5. به Settings → Bindings بروید و یک D1 database binding اضافه کنید:
   - Variable name: DB
   - D1 database: sahroud-family-guard
6. در Settings → Variables and Secrets متغیر متنی زیر را اضافه کنید:
   - Variable name: ALLOWED_ORIGIN
   - Value موقت: https://example.invalid

   پس از ساخت Pages، این مقدار را با نشانی دقیق Pages عوض می‌کنید. مقدار * نگذارید.
7. دوباره Deploy کنید.
8. آدرس Worker را یادداشت کنید؛ شکل آن معمولاً https://sahroud-family-guard-api.ACCOUNT.workers.dev است.
9. آدرس /health را در مرورگر باز کنید. باید پاسخ سلامت سرویس دریافت شود.

## بخش ۳ — انتشار پنل والدین با Pages

1. در Workers & Pages → Create → Pages → Connect to Git، مخزن GitHub با نام sahroud/danky را انتخاب کنید.
2. شاخهٔ تولید را main قرار دهید.
3. تنظیمات ساخت:
   - Framework preset: None
   - Build command: خالی / بدون دستور
   - Build output directory: family-guard/dashboard
4. پروژه را ایجاد و منتظر پایان Deploy بمانید.
5. نشانی Pages که معمولاً به pages.dev ختم می‌شود را کپی کنید.
6. به Worker برگردید و مقدار ALLOWED_ORIGIN را دقیقاً برابر origin پنل قرار دهید؛ برای مثال https://PROJECT.pages.dev، بدون مسیر انتهایی.
7. Deploy مجدد Worker.

## بخش ۴ — تکمیل تنظیمات مخزن و اتصال گوشی

فایل wrangler.toml دارای مقدار جایگزین برای Database ID است:
https://github.com/sahroud/danky/blob/main/family-guard/server/wrangler.toml

اگر از Wrangler در رایانه استفاده می‌کنید، مقدار REPLACE_WITH_YOUR_D1_DATABASE_ID را با شناسهٔ واقعی D1 عوض کنید. این فایل نباید شامل کلید والد، توکن دستگاه یا رمز محرمانه باشد.

در پنل Pages، نشانی Worker را در کادر «نشانی API سرور» وارد کنید. سپس:
1. در پنل، خانواده را ایجاد کنید و کلید والد را در جای امن نگه دارید.
2. برای گوشی عضو یک کد دعوت بسازید.
3. در گوشی عضو، اپ SAHROUD FAMILY GUARD را باز کنید و API URL و کد دعوت را وارد کنید.
4. صاحب گوشی باید گزینهٔ رضایت به اشتراک‌گذاری موقعیت را خودش فعال و اتصال را تأیید کند.
5. مجوز مکان‌یابی را در Android فقط در حد نیاز برنامه بدهید و سرویس اشتراک‌گذاری را آگاهانه روشن کنید.

## چک‌لیست آزمایش پیش از استفاده

- [ ] /health پاسخ موفق می‌دهد.
- [ ] پنل Pages باز می‌شود و origin آن دقیقاً در ALLOWED_ORIGIN ثبت شده است.
- [ ] ایجاد خانواده و ساخت کد دعوت کار می‌کند.
- [ ] اتصال گوشی عضو فقط پس از رضایت صریح انجام می‌شود.
- [ ] موقعیت ثبت‌شده همراه زمان ثبت و زمان دریافت نمایش داده می‌شود؛ موقعیت قدیمی به‌عنوان زنده معرفی نمی‌شود.
- [ ] توقف اشتراک‌گذاری از گوشی عضو و لغو دسترسی از پنل والد هر دو آزمایش می‌شوند.
- [ ] قطع GPS یا اینترنت به‌عنوان قطع ارتباط/قدیمی‌شدن موقعیت نمایش داده می‌شود، نه موقعیت زنده.

## نکات امنیتی و محدودیت‌های نسخهٔ فعلی

این نسخه هنوز برای عرضهٔ عمومی یا استفادهٔ حساس تأیید نشده است. پیش از بهره‌برداری واقعی باید احراز هویت و بازیابی حساب والد، محدودسازی نرخ درخواست‌ها و تلاش کد دعوت، چرخش توکن‌ها، ثبت رخدادهای امنیتی، سیاست نگهداری و حذف داده، پشتیبان‌گیری، پایش و آزمون بار و امنیت اضافه و بررسی شوند. API فعلی مسیر کامل تاریخچه را در پنل نشان نمی‌دهد و فقط آخرین موقعیت را برمی‌گرداند. برای ظرفیت ۱۰۰۰ یا ۱۰۰هزار کاربر، صرفاً طراحی اولیه کافی نیست و آزمون بار و تنظیم منابع Cloudflare لازم است.

هرگز از این سامانه برای ردیابی پنهانی استفاده نکنید. صاحب گوشی باید بتواند اشتراک‌گذاری را متوقف کند؛ خاموش‌کردن GPS، اینترنت یا مجوز سیستم‌عامل می‌تواند ارسال موقعیت را متوقف کند.
