# مبانی امنیتی مشترک SAHROUD

این الزامات برای تمام محصولات متصل به Cloudflare لازم‌اند.

## اسرار و هویت

- API tokenهای Cloudflare، توکن‌های GitHub، کلیدهای امضا و کلیدهای مدیریتی فقط در Cloudflare Secrets یا مخزن امن رمزها نگهداری شوند.
- Secret هرگز در مخزن عمومی، فایل APK، JavaScript مرورگر یا پیام خطا قرار نگیرد.
- رمز عبور کاربر در SAHROUD Central ذخیره نمی‌شود؛ ورود Google و شماره تلفن با Firebase Authentication انجام می‌شود و Worker فقط Firebase ID token را با امضای RS256، issuer، audience و claimهای مجاز بررسی می‌کند.
- Firebase UID شناسه خارجی هویت است؛ روش‌های Google و phone باید با قابلیت Link provider به یک UID پیوند بخورند. ادغام خودکار حساب‌ها بر اساس ایمیل ممنوع است.
- Firebase ID token فقط در حافظه/SDK احراز هویت نگهداری و در هدر Authorization ارسال شود؛ در D1، localStorage، URL یا log ثبت نشود.
- SMS Phone Auth سرویس رایگان نیست؛ پیش از فعال‌سازی Billing باید هزینه، کشورهای مجاز، reCAPTCHA و محدودیت ارسال پیامک بررسی شوند.
- برای کلید تجاری، فقط hash در D1 نگهداری شود؛ متن کامل کلید فقط هنگام صدور نمایش داده شود.
- CORS فقط محدودیت مرورگر است و احراز هویت محسوب نمی‌شود.

## مجوز و چندمستاجری

- همه دسترسی‌ها در سمت سرور کنترل شوند.
- تمام پرس‌وجوهای داده محصول باید به حساب و نقش احراز‌شده محدود شوند.
- شناسه حساب، دستگاه یا پروژه که از کلاینت آمده به‌تنهایی مجوز نیست.
- نقش‌های owner، admin، member و billing باید حداقل دسترسی لازم را داشته باشند.
- کلید/مجوز یک محصول نباید برای محصول دیگر معتبر باشد.
- D1 قابلیت Row-Level Security خودکار ندارد؛ در دیتابیس اشتراکی هر query باید در Worker با product_key و account_id محدود شود.
- اطلاعات حساس یا پرحجم به‌جای pooled D1 در D1 اختصاصی محصول قرار گیرد.

## حریم خصوصی و مرزبندی اطلاعات

- D1 مرکزی فقط حساب، هویت، عضویت، کاتالوگ، اشتراک و مجوز را نگه می‌دارد.
- داده‌های مکانی، سلامت، مهندسی و اطلاعات شخصی در D1 اختصاصی محصول یا مخزن اشتراکیِ کنترل‌شده برای داده کم‌حساسیت می‌مانند؛ هرگز وارد D1 مرکزی نمی‌شوند.
- در audit event فقط metadata غیرحساس ثبت شود؛ رمز، توکن، مختصات دقیق و محتوای خصوصی در log نوشته نشود.
- هر محصول باید دوره نگهداری، حذف، خروجی گرفتن و پاسخ به درخواست حذف را تعریف کند.
- رهگیری مکان فقط با اطلاع روشن، رضایت قابل لغو و امکان توقف روی دستگاه مجاز است.

## API و شبکه

- HTTPS الزامی است.
- پاسخ‌های API حساس باید cache نشوند.
- CORS فقط Originهای دقیق و لازم را بپذیرد.
- درخواست‌های ورودی باید از نظر اندازه، نوع داده و محدوده مقدار اعتبارسنجی شوند.
- برای endpointهای عمومی/حساس rate limiting متناسب تنظیم شود. Rate Limiting معمول Workers تقریبی و به تفکیک محل Cloudflare است؛ آن را جایگزین کنترل سخت امنیتی ندانید.
- خطاهای عمومی جزئیات داخلی، SQL یا stack trace را افشا نکنند.

## استقرار و عملیات

- توسعه محلی با D1 محلی انجام شود؛ D1 راه‌دور staging فقط وقتی ساخته شود که نیاز و سهمیه حساب بررسی شده باشد.
- migration اعمال‌شده را ویرایش نکنید؛ migration جدید بسازید.
- پیش از migration تولید، نسخه پشتیبان و طرح بازگشت داشته باشید.
- شاخص‌های مصرف D1، Workers و ذخیره‌سازی پایش شوند.
- پیش از اعلام آمادگی عمومی، آزمون مجوز، حریم خصوصی، بار، بازیابی و توقف اشتراک‌گذاری اجرا شود.

هسته مرکزی health و کاتالوگ عمومی را ارائه می‌کند. مسیرهای اولیه Firebase session و /v1/me در شاخه توسعه پیاده‌سازی شده‌اند؛ تا ثبت FIREBASE_PROJECT_ID و آزمون واقعی Google و SMS، احراز هویت تولید فعال نیست. صدور مجوز، پرداخت و دسترسی محصول هنوز تکمیل نشده‌اند.
