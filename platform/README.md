# SAHROUD CENTRAL

هسته مرکزی مشترک محصولات SAHROUD. این سرویس به‌صورت مستقل از برنامه‌های موجود توسعه می‌یابد و در این مرحله فقط API پایه و فهرست محصولات را ارائه می‌کند.

## اصول معماری

- هر محصول مستقل باقی می‌ماند و فقط از سرویس‌های مشترک موردنیاز استفاده می‌کند.
- هویت و مجوز محصول از داده‌های عملیاتی همان محصول جداست.
- داده‌های حساس اختصاصی، از جمله موقعیت‌های FAMILY GUARD، در پایگاه داده همان محصول باقی می‌مانند و به پایگاه داده مرکزی منتقل نمی‌شوند.
- هیچ رمز عبور، کلید API، توکن واقعی یا مقدار محرمانه‌ای در مخزن نگهداری نمی‌شود.
- فعال‌سازی حساب، اشتراک، پرداخت و صدور مجوز تا زمان انتخاب و پیاده‌سازی روش احراز هویت و درگاه پرداخت، عمداً فعال نشده‌اند.

## ساختار

- `src/index.js`: Cloudflare Worker API
- `migrations/0001_core.sql`: طرح اولیه پایگاه داده مرکزی؛ هنوز روی Cloudflare اجرا نشده است.
- `test/worker.test.js`: آزمون‌های پایه با Node.js
- `wrangler.toml`: پیکربندی Worker مستقل

## API فعلی

- `GET /health`: سلامت سرویس
- `GET /v1/version`: نسخه API
- `GET /v1/catalog/products`: فهرست محصولات

این نسخه هنوز احراز هویت، مدیریت حساب، پرداخت، اشتراک یا اعتبارسنجی مجوز را انجام نمی‌دهد و نباید برای این موارد در محصول زنده استفاده شود.

## توسعه و آزمون

نیازمند Node.js 20 یا جدیدتر:

```sh
npm test
npx wrangler dev
```

## استقرار Cloudflare

این Worker باید به‌صورت یک سرویس مستقل با Root directory برابر `platform` از مخزن `sahroud/danky` متصل شود. نام Worker پیشنهادی `sahroud-central-api` است.

پیش از استقرار عمومی:
1. یک D1 مستقل با نام `sahroud-central` ایجاد کنید.
2. migration شماره 0001 را پس از بازبینی روی همان D1 اجرا کنید.
3. D1 را با نام binding برابر `CORE_DB` متصل کنید.
4. فهرست originهای واقعی وب‌اپ‌ها را در متغیر `CORS_ALLOWED_ORIGINS` قرار دهید؛ مقادیر با کاما جدا شوند و از wildcard استفاده نشود.
5. احراز هویت، کنترل دسترسی، محدودسازی نرخ، ثبت رویدادهای امنیتی و آزمون امنیت را پیش از فعال‌سازی endpointهای حساس تکمیل کنید.

شناسه D1 و secretها نباید در Git ثبت شوند. این مخزن عمومی است؛ فقط تنظیمات غیرمحرمانه در آن قرار می‌گیرد.
