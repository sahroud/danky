# SAHROUD CENTRAL

هسته زیرساخت مشترک محصولات SAHROUD روی Cloudflare. این پروژه لایه کنترل مرکزی است که محصولات فعلی و آینده از قرارداد مشترک آن استفاده می‌کنند؛ نه یک پنل رهگیری یا یک محصول منفرد.

## معماری مصوب

### لایه مرکزی (Control Plane)

- Worker ثابت: `sahroud-central-api`
- D1 ثابت: `sahroud-central` با binding برابر `CORE_DB`
- داده‌های مرکزی: هویت، حساب شخصی/سازمانی، عضویت، کاتالوگ محصولات، طرح‌ها، اشتراک‌ها، مجوزها و رویدادهای ممیزی
- API نسخه‌دار: همه مسیرهای عمومی زیر `/v1/` قرار می‌گیرند.

### لایه محصولات (Product Data Plane)

کد و داده عملیاتی محصولات از لایه مرکزی جدا می‌مانند. جداسازی منطقی محصول الزاماً به معنی ساخت D1 فیزیکی برای تک‌تک محصولات نیست؛ تخصیص منبع با توجه به حساسیت داده، حجم، نیاز بازیابی و سهمیه حساب انجام می‌شود.

- داده بسیار حساس یا پرحجم، مانند موقعیت و مسیر FAMILY GUARD، در D1 اختصاصی همان محصول می‌ماند.
- محصولات کم‌حساسیت فقط با جداسازی کامل `product_key` و `account_id` در Worker می‌توانند از D1 اشتراکی استفاده کنند.
- D1 مرکزی هرگز محل نگهداری مختصات، اطلاعات سلامت، فایل خصوصی یا محاسبات عملیاتی محصول نیست.
- سرویس موجود `sahroud-counter` برای آمار رضایت‌محور همه محصولات حفظ می‌شود؛ Worker یا D1 تکراری برای آمار هر اپ ایجاد نکنید.

## سیاست تخصیص منابع

| منبع | نام / الگو | قاعده |
|---|---|---|
| Worker مرکزی | `sahroud-central-api` | فقط API کنترل مرکزی و کاتالوگ |
| D1 مرکزی | `sahroud-central` | فقط کنترل مرکزی |
| Worker آمار مشترک | `sahroud-counter` | رویدادهای آمار رضایت‌محور محصولات |
| Worker محصول | `sahroud-<product>-api` | منطق اختصاصی محصول در صورت نیاز |
| D1 اختصاصی | `sahroud-<product>` | برای داده حساس یا پرحجم |
| D1 اشتراکی کم‌حساسیت | `sahroud-products-pool-01` | نام رزروشده؛ فعلاً ایجاد نشود |
| Pages | `sahroud-<product>-dashboard` | پنل وب محصول |
| R2 | پیشوند کلید `/<product>/<account_id>/` | فایل‌های حجیم، فقط از مسیر Worker |

منابع اختیاری مانند R2، KV، Queues و Durable Objects بی‌دلیل ساخته نمی‌شوند. ابتدا از امکانات موجود و سهمیه رایگان استفاده می‌کنیم.

## قرارداد API فعلی

- `GET /health` — سلامت Worker و اتصال D1 مرکزی
- `GET /v1/version` — نسخه API
- `GET /v1/catalog/products` — کاتالوگ از D1 مرکزی
- `GET /v1/catalog/products/{product_key}` — اطلاعات عمومی محصول

API فعلی فقط خواندنی است. ورود کاربر، ایجاد حساب، صدور/ابطال کلید، فعال‌سازی اشتراک، پرداخت و اعتبارسنجی مجوز هنوز فعال نیستند. این محدودیت عمدی است تا روش احراز هویت و مدیریت امن کلید قبل از فعال شدن دسترسی‌ها تعیین شود.

## ساختار پوشه

- `src/index.js` — Worker مرکزی

- `test/schema.test.py` — اعتبارسنجی همه migrationها با SQLite
- `wrangler.toml` — نام Worker، binding پایگاه داده و مسیر migration
- `CLOUDFLARE-RESOURCE-MAP.md` — نقشه منابع مشترک
- `PORTFOLIO-INVENTORY.md` — فهرست محصولات فعلی

## توسعه محلی

نیازمند Node.js 20 یا بالاتر:

1. وارد پوشه `platform` شوید.
2. دستور `npm install` را اجرا کنید.
3. دستور `npm test` و سپس `python test/schema.test.py` را اجرا کنید.
4. برای توسعه از `npm run dev` و D1 محلی Wrangler استفاده کنید.
5. برای آزمون اولیه نیازی به ساخت D1 راه‌دور جداگانه نیست.

## استقرار اولیه

پیش از ایجاد منبع، موجودی Workers و D1 حساب Cloudflare و سهمیه را بررسی کنید. فقط یک D1 مرکزی با نام `sahroud-central` لازم است. راه‌اندازی کامل در [CLOUDFLARE-SETUP.md](./CLOUDFLARE-SETUP.md) مستند شده است.

در طرح رایگان D1 حداکثر ۱۰ دیتابیس برای کل حساب و مجموعاً ۵ گیگابایت فضای ذخیره‌سازی وجود دارد؛ این سقف شامل منابع موجود سایر محصولات است. طرح رایگان ظرفیت نامحدود یا تضمین ظرفیت ۱۰۰ هزار کاربر نیست.

## امنیت و حریم خصوصی

- اطلاعات حساس محصول فقط در دیتابیس یا مخزن اختصاصی همان محصول نگهداری می‌شود.
- secretها هرگز در Git، APK یا JavaScript مرورگر قرار نمی‌گیرند.
- CORS جایگزین احراز هویت نیست.
- مجوزها باید در سمت Worker اعتبارسنجی شوند.
- رهگیری مکان فقط با رضایت روشن و قابل لغو صاحب دستگاه مجاز است.
