# SAHROUD CENTRAL

هسته زیرساخت مشترک محصولات SAHROUD روی Cloudflare. این پروژه «صفحه رهگیری فرزند» یا یک محصول مستقل نیست؛ لایه کنترل مرکزی است که محصولات فعلی و آینده از قرارداد مشترک آن استفاده می‌کنند.

## معماری مصوب

### لایه مرکزی (Control Plane)

- Worker: نام ثابت sahroud-central-api
- D1: نام ثابت sahroud-central و binding برابر CORE_DB
- مالکیت داده: حساب‌ها، هویت‌های متصل، عضویت حساب‌ها، کاتالوگ محصولات، طرح‌ها، اشتراک‌ها، مجوزها و رویدادهای حسابرسی
- API نسخه‌دار: مسیرهای /v1/ برای جلوگیری از شکستن اتصال نسخه‌های قدیمی

### لایه اختصاصی محصولات (Product Data Plane)

هر محصولی که داده عملیاتی دارد Worker و D1 اختصاصی خود را دارد. برای نمونه:

- FAMILY GUARD: Worker اختصاصی و D1 اختصاصی با موقعیت‌ها و مسیرها
- STEEL: محاسبات و پروژه‌های مهندسی در فضای داده اختصاصی
- METREH: متره و برآورد در فضای داده اختصاصی
- UTM: داده‌های نقشه‌برداری و نقاط در فضای داده اختصاصی
- TASBIH: تنظیمات و داده‌های شخصی در فضای داده اختصاصی

داده عملیاتی یا حساس یک محصول به D1 مرکزی منتقل نمی‌شود. جداسازی حساب و مجوز مرکزی به معنی تجمیع اطلاعات خصوصی همه محصولات در یک دیتابیس نیست.

## منابع Cloudflare و قواعد استفاده

| منبع | نام/قاعده | استفاده |
|---|---|---|
| Workers | sahroud-central-api | API مشترک و کاتالوگ |
| D1 | sahroud-central | فقط هویت، عضویت، محصول، اشتراک و مجوز |
| Worker اختصاصی | sahroud-<product>-api | منطق و API محصول |
| D1 اختصاصی | sahroud-<product> | داده عملیاتی همان محصول |
| Pages | sahroud-<product>-dashboard | پنل وب هر محصول |
| R2 | نام‌گذاری با پیشوند محصول و حساب | فایل‌های حجیم، خروجی و پیوست فقط در صورت نیاز واقعی |
| KV | فقط برای cache یا تنظیمات کم‌تغییر | منبع اصلی داده و مجوز نیست |
| Queues / Durable Objects | فقط با نیاز اثبات‌شده | در گام اول ایجاد نشوند |

منابع اختیاری مثل R2، KV، Queues و Durable Objects را از ابتدا بی‌دلیل نمی‌سازیم؛ اضافه‌کردن آنها باید متناسب با قابلیت موردنیاز، هزینه و محدودیت طرح انتخاب شود.

## قرارداد API فعلی

- GET /health — سلامت Worker و اتصال D1 مرکزی
- GET /v1/version — نسخه API
- GET /v1/catalog/products — کاتالوگ زنده از D1 مرکزی
- GET /v1/catalog/products/{product_key} — اطلاعات عمومی یک محصول

فعلاً API فقط خواندنی است. ورود کاربر، ایجاد حساب، صدور/ابطال کلید، فعال‌سازی اشتراک، پرداخت و اعتبارسنجی مجوز هنوز فعال نیستند. این محدودیت عمدی است تا ابتدا تأمین‌کننده هویت، سیاست نقش‌ها و روش امن مدیریت کلید تعیین شود. هیچ محصولی نباید تا آن زمان دسترسی تجاری را صرفاً براساس پاسخ ساختگی یا کلید ثابت داخل برنامه فعال کند.

## توسعه محلی

نیازمند Node.js 20 یا بالاتر:

1. وارد پوشه platform شوید.
2. دستور npm install را اجرا کنید.
3. دستور npm test را اجرا کنید.
4. برای توسعه محلی، شناسه D1 واقعی در فایل wrangler.toml لازم نیست تا وقتی از D1 محلی استفاده می‌کنید؛ اما binding و migration باید تعریف شده باشند.
5. برای اجرای محلی، از npm run dev استفاده کنید.

## استقرار اولیه

1. در Cloudflare یک D1 با نام sahroud-central بسازید.
2. Database ID را در platform/wrangler.toml در جای placeholder قرار دهید. Database ID شناسه محرمانه یا رمز عبور نیست، اما هیچ API token یا کلید مخفی را در Git قرار ندهید.
3. migrationها را با npm run db:migrate:remote اجرا کنید. در محیط داشبورد نیز می‌توان محتوای migration را در کنسول D1 اجرا کرد؛ فقط یک روش را انتخاب کنید و از اجرای دستی تکراری خودداری کنید.
4. Worker را با نام sahroud-central-api و Root directory برابر /platform به GitHub متصل کنید.
5. Deploy command برابر npm run deploy باشد.
6. پس از انتشار، /health را بررسی کنید؛ مقدار dependencies.core_db باید ok باشد.
7. مسیر کاتالوگ باید محصولات ثبت‌شده در D1 را برگرداند.

## محیط‌ها و پایداری

برای توسعه، آزمایش و تولید باید شناسه‌ها و پایگاه‌های جداگانه استفاده شود. هیچ‌گاه migration آزمایشی را روی D1 تولید اجرا نکنید. پیش از تغییر schema در تولید، نسخه پشتیبان و برنامه بازگشت داشته باشید.

در طرح رایگان D1، سقف حساب ۱۰ دیتابیس، حداکثر اندازه هر دیتابیس ۵۰۰ مگابایت و سقف فضای کل حساب ۵ گیگابایت است. این سقف شامل دیتابیس‌های موجود حساب هم می‌شود. بنابراین قبل از ساخت هر D1 جدید، فهرست و تعداد دیتابیس‌های موجود بررسی شود. برای هر کاربر یا خانواده دیتابیس جدا نسازید؛ داده چندمستاجری هر محصول با account_id در دیتابیس همان محصول جدا می‌شود.\n\nبرای جلوگیری از مصرف بی‌دلیل سهمیه رایگان، توسعه و آزمون اولیه از D1 محلی Wrangler استفاده می‌کند. دیتابیس Remote staging فقط پس از بررسی ظرفیت حساب ساخته می‌شود؛ برای اولین استقرار، فقط یک D1 مرکزی با نام sahroud-central لازم است.\n\nطرح رایگان Cloudflare برای شروع و آزمایش مناسب است، اما محدودیت سهمیه و نبود تضمین ظرفیت به معنی تضمین سرویس برای ۱۰۰ هزار کاربر نیست. پیش از رشد به این مقیاس، آزمون بار، پایش سهمیه، پشتیبان‌گیری، محدودسازی درخواست‌ها و بررسی هزینه لازم است.
